How it works

Not one giant chat. A small AI dev shop on your PC.

VibeSquad runs the coding-agent CLIs you already have signed in (Claude Code, Gemini / Antigravity, OpenCode and Codex) as separate agents with separate jobs. You talk to a Buddy who plans, a Lead hands out the work, and short-lived Workers each do one task. A hub Lead called the Overlord looks after the whole Squad.

Talk track: "Instead of one chat that grows until it forgets things, each job gets its own agent, and agents pass files to each other, not chat history."

Two kinds of rules appear below. A prompt rule is something agents are told to do. A server check is code that refuses the action. They are tagged so you can tell them apart.

03 / Who does what

Roles

What each role is told to do is a prompt rule (server/profiles.mjs). Only the items in the green box are enforced by code.

Owner (you)

Sets direction and talks to the Buddy. Release publishing is yours: agents are told to hand a release request to the Release Desk and never publish themselves.

Buddy

The chat you talk to. Plans the work in a plan file and hands build work to a Lead rather than writing the code.

Lead

Splits the plan into blocks, dispatches Workers, reads their reports and merges after review.

Worker

Does one block in its own git worktree and reports PASS/FAIL in its final message. In the team log, Leads and Buddies write the entries; a Worker may write only metric and its own done/blocker entries (cli/vs.mjs:545-549).

Reviewer

A separate agent checks a Worker's diff. The Lead's prompt pairs Claude work with a Gemini reviewer and Gemini work with a Sonnet reviewer (server/profiles.mjs:64); nothing in code forces it.

Overlord

The hub Lead of a Squad. It is the only role allowed to start a Lead on another lane of its own Squad.

What the server does check today

  • Starting a Lead: only a Buddy (for its own lane) or the Squad's hub Lead may, the lane must exist in the team registry, the profile must be a Lead profile, and a lane with a live Lead is refused (server/mcp/tools.mjs:342-395). Role, ordinal and handoff labels supplied by the caller are stripped.
  • The Overlord handing off a healthy Lead under the token floor is refused unless forced with a written steer note (server/lead-handoff.mjs:223-237).

What it does not check: that a Worker may not start other Workers, who may publish a release, or which reviewer is used. Those are prompt rules. Agent identity comes from the runner's per-agent token, but the older tokenless fallback is still on unless VS_AGENT_TOKEN_REQUIRED=1 is set (server/backend/runner-client.mjs:38), so don't read it as a security boundary yet.

04 / The app

Two looks, and a phone you can pair

Chosen on first launch, switchable any time in Settings.

Normal vs Psycho

Normal is a plain layout: a sidebar of projects, a centered chat and project cards. Psycho is the pixel-art Vibespace office. The Phone Cockpit labels Normal as Corpo (src/PhoneCockpit.tsx:273), and Settings search also finds it under "corpo" (src/prefs.ts:113). The CRT button in this page's header is only a taste of Psycho.

Pairing a phone

  • On the PC, open Pair a Device: scan the QR, or type the 6-digit one-time code (valid for about a minute, server/auth.mjs:1007).
  • The window shows the CA SHA-256 fingerprint to compare with the phone. Other devices stay off by default (loopback only) until you turn on remote access.
  • Every paired device has a Revoke button that signs it out at once.
  • The vs CLI and MCP tools check an HMAC proof from the local server before sending the local token.
  • An end-to-end encrypted relay exists but is off by default: it only starts if you hand-edit a wss:// endpoint into your settings file. No hosted relay ships. When one is running, Pair a Device also offers a relay link.
