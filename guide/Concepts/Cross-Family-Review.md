# Cross-family review

A model shares its own blind spots. If one model writes the work and the same kind of model reviews it, the same mistake can pass twice.

The rule: the reviewer is never from the same model family as the author.

How to use it:

- Pair them. If one family writes it, a different family reviews it.
- Give the reviewer one job: list problems, with the file, the line and the command that shows each one. It does not fix anything.
- The Lead checks at least one claim from any report against the real files.
- If you only have one family, use a fresh session on a different tier, and write that down.

The pairing list lives in [LEAD_RULES.md](../Setup/templates/LEAD_RULES.md), rule 4.
