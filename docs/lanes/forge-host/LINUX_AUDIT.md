# Linux readiness audit: VS engine room on a Linux forge host

Read-only audit of this checkout (static: grep plus targeted reads). Nothing was run on Linux, so every row is a code-reading
finding, not a test result. Scope: server, runner, agents, repos/worktrees, test suites, Godot headless. Paths are repo-relative;
`~` is the home dir of the user running VS.

The code base is already largely cross-platform (most Windows branches have a POSIX twin, see the "Already cross-platform" list).
The problems cluster in three places: the **runtime-dir / build-stamp model** (Windows-only layout), **process-tree handling in the
runner** (Windows `taskkill /T` has no POSIX equivalent wired up), and **tooling the POSIX branch assumes is installed** (`lsof`).

Severity key: blocker = the engine room does not work or silently runs wrong code; high = breaks a core flow in common setups;
med = degrades a feature or a test lane; low = cosmetic, Windows-only tooling not needed on the forge.

## Already cross-platform (verified)

- Process-tree kill, server side: `server/proc-tree.mjs:7-24` (taskkill on win32; POSIX kills group then pid; children started `detached`).
- Restart script POSIX branches: process info via `ps` (`scripts/restart-runtime.mjs:210-230`), SIGTERM/SIGKILL (:264-273), detached spawn with log fd (:276-285), bundled node falls back to `process.execPath` (:429-430), `VS_CLI` identity checks work on POSIX command lines (:242).
- `vs restart` launch: non-win32 path spawns the script detached with agent env stripped (`cli/vs.mjs:2914-2923`); WMI/PowerShell only on win32 (:2907).
- Runner process inspection: `ps -o etimes=,comm=` with 15-char comm truncation handled (`runner/children.mjs:26-28, 60`); full table via `ps -A` (`runner/background.mjs:62, 84-91`); shell names include bash/sh/zsh (:9).
- Home/runtime-adjacent paths honoring env: `VIBESQUAD_HOME` else `~/.vibesquad` (`server/teams-file.mjs:24-26`, `server/push.mjs:10-12`, `scripts/run-tests.mjs:34`, `server/test-guard.mjs:14-19`).
- Worktree sanctuary: `VIBESQUAD_WORKTREES_DIR` or `~/.vibesquad/worktrees` on POSIX (`server/team-worktrees.mjs:126-134`).
- node_modules link: `symlinkSync(..., "junction")` is ignored on POSIX and creates a dir symlink (`server/team-worktrees.mjs:180`; `cli/vs.mjs:1583`); link removal via `unlink` then `rmdir` (`team-worktrees.mjs:193-207`, `server/disk-dedupe.mjs:105-114`); file symlink/exec-bit restore handled (`team-worktrees.mjs:1748, 1855-1858`).
- Case-insensitive path compares are win32-only and exact elsewhere (`server/team-worktrees.mjs:279, 572`, `server/git-api.mjs:345`, `server/vibesquad-api.mjs:784`, `runner/drain-hook.mjs:50`, `server/brief-path.mjs:85`). A scripted check of every relative import in server/cli/runner/scripts/test/src (788 files) found **0** case mismatches and `git ls-files` has no case-colliding names, so a case-sensitive FS is safe.
- Line endings: `.gitattributes:2` is `* text=auto eol=lf`; parsers use `\r?\n` (e.g. `server/team-worktrees.mjs:186`, `runner/background.mjs:86`).
- File locks and liveness: O_EXCL lock files with POSIX `pidAlive` (`runner/lock.mjs:57-63`, `server/file-lock.mjs`, `scripts/suite-lock.mjs`); the EPERM/EBUSY retries only add tolerance.
- Secrets perms: 0700 home / 0600 key files off win32 (`server/auth.mjs:226-232, 310, 364`; `runner/server.mjs:392`).
- Terminals and workspace scripts: `$SHELL` or `/bin/bash`, `detached` on POSIX (`server/terminals.mjs:30-33, 92`; `server/workspace-scripts.mjs:28, 62`); `rg` lookup without `.exe` (`server/file-search.mjs:114`).
- Runner spawns never use a shell and pass fixed arg lists (`runner/spawn.mjs:48-54`); background-shell kill falls back to `kill(-pid)` (`runner/spawn.mjs:94`) once the leader issue in rank 4 is fixed.
- Listen address: server and runner bind `127.0.0.1` (`server/serve.mjs:493`, `runner/server.mjs:460`); no firewall/netsh/registry/schtasks calls exist in server/cli/scripts/runner (grep clean), so nothing there needs porting; the only OS firewall step is allowing the chosen interface/port.
- Process-list helpers: `server/unstick.mjs:29-55`, `scripts/test-watchdog.mjs:32-41` have `ps -eo` branches.
- CI workflows run on `ubuntu-latest` already (`.github/workflows/*.yml`).

## Not checked / unsure

- Nothing was executed on Linux: no `npm ci`, no `npm test`, no restart cycle. Expect some of the ~190 test files with Windows literals to fail for reasons outside the rows above.
- Godot: path, headless flags, `run_godot.sh`, `timeout.exe`, export templates and the EFI suites live in the EFI repo(s), not here (rank 17).
- `node-pty` (`package.json:49`, optional beta, native build) on Linux: needs build tools or a prebuilt; the piped fallback in `server/terminals.mjs` covers absence, but behavior was not run.
- Whether `process.on('SIGBREAK')` is silently accepted on Linux Node (believed yes).
- Provider CLIs themselves: Linux availability and flags of `agy`/`antigravity`, `opencode`, `codex`, and Claude Code's Linux sandbox/shell-snapshot behavior (`runner/background.mjs:13` matches the `shell-snapshots` marker); credentials locations under `~/.claude`, `~/.gemini` are assumed the same.
- Playwright MCP and Chrome/Edge availability for the UI lanes (rank 8) and Meshnet-side TLS/CA trust for phones (`server/auth.mjs` CA flow) were not traced end to end.
- Per-user resource limits (open files, inotify, pids) and disk layout of `~` on the forge were not assessed.
- `src-tauri/` (desktop shell) was out of scope: not built on the forge.
- Docs/skills text that tells agents to run PowerShell or Windows commands (docs/WORKFLOWS.md, profiles under `docs/profiles`) was not swept; grep it before cut-over.
