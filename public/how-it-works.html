LOCAL-FIRST MULTI-AGENT DEV SHOP · NODE.JS 22 + TAURI 2 (RUST)

Not one giant chat. A real AI dev shop on your PC.

VibeSquad supervises real coding-agent CLIs you already have logged in (Claude Code, Gemini / Antigravity, OpenCode, and Codex) like staff on shifts. You set direction, a hub boss called the Overlord runs operations, and short-lived Workers do one task each in isolated git worktrees under cross-family review gates.

How Requests Flow Down:
1. You talk to UI (Web / Desktop / Phone) 2. Server checks perms & layers prompt 3. Runner supervises child CLI process 4. Hub coordinates parallel Feature Teams
THE 15-SECOND SUMMARY

The Buddy spawns a Lead, the Lead dispatches parallel single-task Workers into isolated git worktrees, a rival AI family reviews the diff, and an ops boss called the Overlord merges it and handles server restarts."

03 / How Work Changes Hands

        
No Handoff Ever Passes a Chat Transcript

        

          Every transition in VibeSquad passes files (the Team brief, a plan, a handoff packet) and labels, while the server enforces the caller's role from the runner's own record.
        

      


      
      

        
        

          Talk Track:
          "In normal agent frameworks, handing off means forwarding a giant message history until the next agent chokes. In VibeSquad, zero chat transcripts are passed. Agents hand off files—briefs, plans, and handoff packets—and the server enforces who is allowed to trigger each handoff."

Inside a Lead Handoff (150k / 250k / 300k)

          

            A Lead handoff is a deterministic server routine, not a prompt the agent is trusted to follow:
          


          

            

              
1. Compact-First (150k tokens while idle)

              
Runs /compact in place keeping plan, blocks & worker IDs. 80% success rate (−92% tokens: 152k → 11.8k). If clean, handoff ends right here!

            

            

              
2. Soft Flag (150k tokens)

              
Nudges Lead: stop dispatching, let Workers finish, write hand-authored Judgment section, run handoff_lead.

            

            

              
3. Server Packet Fallback

              
If the Lead didn't write a packet, the server generates it: lane/ord, open Workers, last 30 lane log entries, and Team brief (never overwrites a Lead-written packet).

            

            

              
4. Successor Spawn (250k auto or manual)

              
Starts ord+1 on a profile from routing policy (so quota rebalance sticks). Inlines packet, brief & Overlord steer (≤2,000 chars) between BEGIN/END with code fences defanged.

            

            

              
5. Re-Point Open Workers & Auto-Redirect Sends

              
Moves open Workers' vs.parent label to successor and automatically redirects any send aimed at a former-lead to the live successor Lead.

            

          

        

      

    

    
    

      

        
04 / Prompt Layering & Lesson Evolution (server/hooks/agent-duties.ts)

        
Where Agents Get Their Rules (100% Prompt Cache Hit Rate)

        

          Agents aren't asked to look up rules—the server injects them at before("agent.create") in a static, fixed order with zero timestamps or per-spawn variables so the provider's prompt cache hits on every single start.

               Say This Out Loud:
            

            

              "Whenever an agent messes up twice, we write it up in LESSONS.md as Symptom, Root Cause, Rule, and Evidence. If we can enforce it in server code, we make it a hard server check and delete the prompt line so prompts stay tiny."
            

          


          

            
How Rules Are Born (docs/LESSONS.md)

            
            

              
Real Example 1: Standing Rule R13 (2026-11-08)

              
Symptom: Agents kept ending turns asking permission for obvious fixes. An audit of 653 owner inputs found 17 "send it" rubber stamps (and 50 permission-begging outputs in 33,546 turns).

              
Rule R13: "Act on your lean, report after." Ask only for scope changes, outward actions, money, or irreversible deletes.

            


            

              
Real Example 2: The 40–55k Token Duplicate Bug

              
Symptom: Buddies were starting fresh sessions already bloated at 40–55k tokens.

              
Fix: Rules R1–R7 were accidentally injected twice. Now every rule lives in one place and chars=<N> is tracked on every spawn.

             OVERLORD STALLED-LEAD LADDER
          

          
Must Go in Order, Never Skips a Rung

          
          

            

              
Rung 1: Steer (Wait up to 90s)

              
Send the idle or stalled Lead a steer message and wait 90 seconds.

            

            

              
Rung 2: Interrupt & Steer (Wait up to 90s)

              
For a runaway or looping turn: cancel the turn, send the steer, wait 90 seconds.

            

            

              
Rung 3: Take Over (Protected by 100k Floor)

              
Only if steering failed, Lead is errored/wedged, or lane is leaderless: hand off to a fresh successor. Server refuses Overlord handoff of a healthy Lead under 100k tokens ("steer first"); --force requires a written steer and logs a decision.

07 / Why Not Just Use CrewAI, AutoGen, or LangGraph?

        
Library Frameworks vs. VibeSquad Process Supervision

        

          Typical multi-agent frameworks are Python/JS libraries where agents are API calls inside one script and handoffs pass chat arrays. VibeSquad supervises real installed coding CLIs as long-lived OS processes on subscriptions you already pay for.
        

      


      
      

        
        

          Talk Track:
          "People always ask how this differs from CrewAI or LangGraph. Those are code libraries where an 'agent' is just an API call in a loop and roles are just prompt strings. VibeSquad is an OS process supervisor—each agent is a real Claude Code or Gemini CLI process in its own git worktree, and permissions are enforced by the server, not polite prompt instructions."
        

      


      
      

        

          
            

              Concern
              Typical Framework (CrewAI / AutoGen / LangGraph)
              VibeSquad (Local-First Dev Shop Runtime)
            

          
          
            

              What an agent is
              A function call to a model API inside one script
              A separate CLI process (Claude Code, Antigravity, OpenCode, Codex) with its own JSONL log, memory token & git worktree on existing subscriptions
            

            

              Who enforces roles
              The prompt says "you are the manager"
              The server: checks runner's own record so a Worker cannot spawn and a Feature Lead cannot act on another lane
            

            

              Handoff
              Pass the message history array to the next agent
              Pass files (Team brief, plan, handoff packet); successor never sees the old transcript
            

            

              Long runs
              One context grows until quality degrades
              Retired on 150k/250k/300k token budgets & replaced from files (/compact tried first)
            

            

              Review
              Optional, often the same model family
              Mandatory & cross-family by default (Claude ⇄ Gemini) + strict Tier-A gate for security/state
            

            

              Waiting
              Orchestrator awaits or polls in sleep loops
              Event-driven: a log write or vs watch set ping wakes the manager; zero polling

            docs/LESSONS.md
          

          

            VibeSquad wasn't designed on a whiteboard—every piece replaced something that broke in daily use on the old Paseo daemon:
          


          

            

              
Before: paseo ls -g --json every turn

              
Broke: 12k-char lookups & CLI deadlocks

              
Now: vs who lead from labels & registry

            


            

              
Before: Regex on title prefixes (★, BRAINSTORM)

              
Broke: Cross-lane agent collision bug

              
Now: Identity v2: lane label is sole truth

            


            

              
Before: Sibling git worktree folders

              
Broke: 44+ stray folders cluttering projects dir

              
Now: Managed folder + vs worktree sweep

            


            

              
Before: Spawning via Paseo daemon

              
Broke: 121.6s median spawn; restarts killed agents

              
Now: Own Node.js runner (3ms create call)

            


            

              
Before: Sleep loops & heartbeats while waiting

              
Broke: Burned turns and tokens doing nothing

              
Now: vs watch sets: 1 ping when all finish

Normal vs Psycho

          
Normal is a plain layout: a sidebar of projects, a centered chat and project cards. Psycho is the pixel-art Vibespace office. The Phone Cockpit labels Normal as Corpo, and Settings search also finds it under "corpo". The CRT button in this page's header is only a taste of Psycho.

        

        

          
Pairing a phone

          
    
            
  • On the PC, open Pair a Device: scan the QR, or type the 6-digit one-time code (valid for about a minute).
    • 
            
  • The window shows the CA SHA-256 fingerprint to compare with the phone. Other devices are off by default (loopback only) until you turn on remote access.
    • 
            
  • Every paired device has a Revoke button that signs it out at once.
    • 
            
  • The vs CLI and MCP tools check the local server's HMAC proof before sending the local token.
    • 
            
  • An end-to-end encrypted relay exists but is off by default: it only starts if you hand-edit a wss:// endpoint into your settings file. No hosted relay ships. When one is running, Pair a Device also offers a relay link.
